How to stop imports creating duplicate contacts in HubSpot

Most HubSpot duplicates don't come from people typing. They come from imports, forms and integrations creating a new record when one already exists. HubSpot has good built-in matching for imports, but only on a few fields. Once you know which fields, most duplicates are easy to prevent.

How HubSpot decides an imported row already exists

ObjectMatched onWhat happens on a match
ContactsEmail address, or Record IDThe existing contact is updated instead of a new one created
CompaniesCompany domain name, or Record IDThe existing company is updated
Any objectA custom property set to require unique valuesThe existing record is updated

Anything else is not a match. A row with the right name but no email, or a different email, becomes a new contact. A company row with no domain becomes a new company, even if one with the same name exists.

Import checklist

  1. Include the email column, and map it to Email. This is the single biggest fix. Rows without an email can't be matched to anyone.
  2. Clean emails first. Trim spaces, lower-case them and remove obvious junk like "n/a" or "none@none.com". A stray space can stop a match.
  3. For updates, include Record ID. If you exported from HubSpot, edited in a spreadsheet and are importing back, keep the Record ID column and map it. It matches even if the email changed.
  4. For companies, include a clean domain. Use the bare domain (acme.com), not www.acme.com, https://acme.com/ or a full URL with a path. Variants are a common source of duplicate companies.
  5. Choose create-and-update on purpose. In the import options, decide whether rows should create new records, update existing ones, or both. "Update existing only" is the safest choice for enrichment files.
  6. Test with 20 rows. Import a small sample, check that existing contacts were updated and not duplicated, then import the rest.

Company domains and automatic company creation

HubSpot can create and associate companies from contact email domains automatically (a setting under objects, companies). That's useful, but it's another source of duplicates when someone also imports companies by hand with a different domain format, or when a business uses more than one domain. Pick one source of truth for company records, and keep domains in the same bare format everywhere. For more on this, see how to find duplicate companies in HubSpot.

Forms and integrations that create duplicates

  • Forms with optional email. If email isn't required, HubSpot has nothing to match on. Make it required.
  • Same person, new email. Someone who fills in a form with a personal address after first using a work address usually becomes a second contact. Asking for a work email helps, and a regular scan catches the rest.
  • Integrations that "create" instead of "create or update". Zapier, Make, webinar tools and ad lead syncs often have both actions. Use the one that searches by email first.
  • CRM syncs. If you sync with another CRM, check its duplicate settings too. Two systems each creating records can double up quickly.
  • Manual entry. HubSpot warns about an existing email, but not about a similar name at the same company. Remind reps to search before they create.

A 10-minute monthly cleanup routine

  1. Create a saved view of contacts created in the last 30 days, sorted by last name, with company and email domain as columns. Scan it for neighbours that look alike.
  2. Make a view of contacts with no email. Either add the email, or decide whether the record is worth keeping.
  3. Check your list of companies with no domain, and add one where you can.
  4. Merge the real duplicates (export the secondary records first, because merges can't be undone).
  5. Note which source created the duplicates (import, form, integration) and fix that source.

FAQ

How does HubSpot deduplicate contacts on import?

It matches contacts by email address or Record ID, and companies by company domain name or Record ID. Rows that match update the existing record.

Why did my HubSpot import create duplicates?

Usually because rows had no email, a different email, or extra spaces, so HubSpot couldn't match them to the existing contact.

Can I use Record ID to update contacts on import?

Yes. Keep the Record ID column from your HubSpot export and map it when you import the edited file back.

How do I stop forms creating duplicate contacts?

Make email required, ask for a work email, and check that connected tools use a create-or-update action rather than create.

How often should I check for duplicates?

A short monthly check of recently created contacts catches most of them before they spread into lists and reports.
