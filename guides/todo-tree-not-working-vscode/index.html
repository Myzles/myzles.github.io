Todo Tree not working after a VS Code update: how to fix it

Todoscope works in VS Code, Cursor, Windsurf and VSCodium. VS Code Marketplace · Open VSX (Cursor, Windsurf, VSCodium).

You update VS Code, open the TODO panel and it's empty, with this in the corner:

Todo-Tree: Failed to find vscode-ripgrep - please install ripgrep manually
and set 'todo-tree.ripgrep' to point to the executable

This is the most reported Todo Tree problem right now (issues #925, #929, #938 and #939 on its GitHub). The fix takes about two minutes, and you don't have to give up Todo Tree to do it.

Why it broke

Todo Tree doesn't read your files itself. It runs ripgrep (rg), a separate search program, and by default it uses the copy that ships inside VS Code. VS Code 1.122 changed where that bundled copy lives. Todo Tree's last release is 0.0.226 from April 2023, so it still looks in the old place, finds nothing, and gives up.

The way out is to give Todo Tree a ripgrep that doesn't move when VS Code updates.

Fix 1: install ripgrep and point Todo Tree at it

Step 1. Install ripgrep

  • Windows: winget install BurntSushi.ripgrep.MSVC (or choco install ripgrep, or scoop install ripgrep)
  • macOS: brew install ripgrep
  • Ubuntu / Debian: sudo apt install ripgrep
  • Fedora: sudo dnf install ripgrep

Step 2. Find its full path

Open a new terminal (so it picks up the new PATH) and run:

# Windows (PowerShell)
(Get-Command rg).Source

# macOS / Linux
which rg

On macOS this is usually /opt/homebrew/bin/rg (Apple silicon) or /usr/local/bin/rg. On Linux, /usr/bin/rg.

Step 3. Set the right setting

Open settings.json (Command Palette, Preferences: Open User Settings (JSON)) and add the path:

"todo-tree.ripgrep.ripgrep": "C:\\Users\\you\\AppData\\Local\\Microsoft\\WinGet\\Links\\rg.exe"

Use your own path from step 2. On Windows, double the backslashes in JSON, or use forward slashes.

Watch the setting name. The error tells you to set todo-tree.ripgrep. That's the old name, and setting it does nothing. The key that works is todo-tree.ripgrep.ripgrep (Todo Tree issue #930 covers this).

Step 4. Reload

Run Developer: Reload Window, then open the Todo Tree panel. If it's still empty, run Todo Tree: Refresh, and check the Output panel (pick "Todo Tree" in the dropdown) for the path it tried.

Fix 2: Remote SSH, WSL and dev containers

With a remote workspace, Todo Tree runs on the remote machine, so ripgrep has to be there too. Issue #939 describes exactly this: VS Code Server auto-updates into a new folder and Todo Tree loses ripgrep again.

  1. Install ripgrep on the remote host (sudo apt install ripgrep or similar).
  2. Open settings, switch to the Remote tab, and set todo-tree.ripgrep.ripgrep to the remote path, such as /usr/bin/rg.
  3. For dev containers, add ripgrep to your Dockerfile or postCreateCommand so a rebuild doesn't undo it.

What not to do

You'll see advice to point the setting at the ripgrep inside VS Code's own install folder (somewhere under resources/app/node_modules). It works until the next VS Code update, then breaks again, because that folder changes. A ripgrep you installed yourself stays put.

Fix 3: try Better Todo Tree

Better Todo Tree (by FanaticPythoner) is a fork of Todo Tree that is still maintained (version 1.3.4, updated July 2026, on both the VS Code Marketplace and Open VSX). It keeps the Todo Tree way of working, including ripgrep, so it's the closest swap if you like Todo Tree and just want someone fixing bugs. Read its changelog to check how it finds ripgrep on your setup.

Fix 4: use an extension without ripgrep

If you'd rather not depend on an external program at all, I built Todoscope for that reason. It has its own scanner inside the extension, so there's no ripgrep to install or lose after an update, locally or over Remote SSH, WSL and Codespaces. The tree, highlights and filters are free, and the Import Todo Tree settings command copies your tags, colours and regex (including $TAGS).

How I tested it: on VS Code 1.146 its integration tests pass 8 of 8, and 1,000 repeated scans of random public repos gave 0 crashes and 0 changed results. In fairness, ripgrep is faster on very large repos, so if Fix 1 works for you, Todo Tree is a fine choice.

FAQ

Why did Todo Tree stop working after the VS Code update?

Todo Tree doesn't search files itself. It runs ripgrep, and looks for the copy bundled inside VS Code. VS Code 1.122 changed where that copy lives, and Todo Tree (last updated April 2023, version 0.0.226) still looks in the old place.

Which setting do I change, todo-tree.ripgrep or todo-tree.ripgrep.ripgrep?

todo-tree.ripgrep.ripgrep. The error message still says todo-tree.ripgrep, which is the old name. This is reported in Todo Tree issue #930.

Will the fix survive the next VS Code update?

Yes, if you point the setting at a ripgrep you installed yourself, because that path doesn't change when VS Code updates. Pointing it at a file inside the VS Code install folder breaks again on the next update.

Does Todo Tree work over Remote SSH?

It runs on the remote host, so ripgrep has to exist there. Install it on the host (for example /usr/bin/rg) and set todo-tree.ripgrep.ripgrep in the Remote settings, not your local ones.
