How to keep project tasks inside VS Code: TODO comments, a todo.md, or an extension

A question that comes up again and again in VS Code communities: where do you keep the small, project-specific tasks? Not the big tickets in Jira or GitHub Issues, but "handle the empty state here", "rename this after the migration", "remove this hack before release". A separate to-do app adds friction, and those tasks get lost.

Developers mostly settle on one of three approaches, often two together.

Option 1: TODO comments next to the code

Write // TODO: handle empty list right where the work is. The task lives with the code it's about, travels with the branch, and shows up in code review.

  • Good for: anything tied to a specific line or file. This is most small dev tasks.
  • Weak at: seeing them all at once. They're scattered across hundreds of files, and old ones pile up unnoticed.
  • Make it work: agree on a few tags (TODO, FIXME, HACK), add a name or ticket when it matters (TODO(sam):, TODO #142), and use a list view (below) so they don't get lost.

Option 2: a todo.md in the repo

A Markdown checklist (- [ ] update the readme) at the repo root. VS Code renders the preview, and it's versioned with the project.

  • Good for: tasks that aren't about one line: "write release notes", "ask design about icons". Also fine for small teams sharing a private repo.
  • Weak at: staying current. Nothing links it to the code, so finished items linger and new ones get written somewhere else.

Option 3: a task extension or the issue tracker

Some extensions keep a per-workspace task list in VS Code's own storage; the GitHub Pull Requests extension shows your repo's issues in the sidebar.

  • Good for: personal lists that shouldn't be committed, or work that already lives in issues.
  • Weak at: anything tied to code. The task isn't in the file, so it doesn't follow the branch and reviewers can't see it.

A common, low-friction setup is TODO comments for code tasks plus issues for anything bigger, with a list view so the comments never get lost.

Seeing every TODO comment in the project

Without installing anything, use Search (Ctrl+Shift+F) with regex on and search for TODO|FIXME|HACK (turn on Match Whole Word too). It works, but it also matches strings and variable names, and you have to re-run it. There are more free options in how to list all TODOs in VS Code.

FAQ

What is the best way to track tasks inside VS Code?

For code-level tasks, TODO comments next to the code plus a list view that gathers them. For chores not tied to code, a todo.md or your issue tracker works well.

Should TODO comments be committed?

Short-lived ones are fine and help reviewers see unfinished work. Add an owner or ticket to anything that will live longer than the branch, and review old ones regularly.

How do I see all TODO comments in a VS Code project?

Use Search with a regex like TODO|FIXME with Match Whole Word on, or install an extension that lists TODO comments in a tree.

Is a todo.md file better than TODO comments?

They do different jobs. A todo.md suits project chores; TODO comments suit tasks tied to specific code. Many teams use both.

Do TODO extensions work in Cursor?

Most VS Code extensions work in Cursor if they are on Open VSX or installed from a .vsix file. See the guide on TODOs in Cursor.
