How to see all TODOs in Cursor

Todoscope works in VS Code, Cursor, Windsurf and VSCodium. VS Code Marketplace · Open VSX (Cursor, Windsurf, VSCodium).

Cursor is built on VS Code, so everything that lists TODOs in VS Code works the same way in Cursor. The one difference is where extensions come from: Cursor's Extensions view searches Open VSX, not Microsoft's Visual Studio Marketplace. Here are four ways to get the list, starting with no setup at all.

1. Search the whole project

  1. Press Ctrl+Shift+F (Cmd+Shift+F on Mac).
  2. Turn on regex (.*) and match case (Ab).
  3. Search for: 
    \b(TODO|FIXME|HACK|BUG|XXX)\b
  4. Under the three dots, add node_modules, dist, build to files to exclude. Files in .gitignore are skipped already.

Search doesn't know what a comment is, so you'll also get strings like status = "TODO". To keep only tags right after a comment marker, use:

(//|#|/\*|\*|--)\s*(TODO|FIXME|HACK|BUG|XXX)\b

2. Keep the list open in a search editor

Run Search Editor: New Search Editor from the Command Palette (Ctrl+Shift+P), paste the regex, and you get the results as a normal tab you can save as a .code-search file and re-run later. From the terminal, git grep -n -E "\b(TODO|FIXME)\b" does the same.

3. Show TODOs in the Problems panel

Linters know what a comment is, so this is the cleanest built-in option:

  • ESLint: "no-warning-comments": ["warn", {"terms": ["todo", "fixme"], "location": "start"}]
  • Pylint: the fixme check (W0511) is on by default. Ruff: enable the TD and FIX rules.

Open the Problems panel with Ctrl+Shift+M. It mixes TODOs with other warnings and usually covers only files the linter has checked.

4. Install a TODO extension

An extension gives you a live tree of every tag, grouped by file. In Cursor there are two ways to install one:

  • From the Extensions view (Ctrl+Shift+X), if the extension is on Open VSX. Todo Tree is there, but Open VSX has version 0.0.215 (2022), older than the 0.0.226 on Microsoft's store. Better Todo Tree, a maintained fork, is on Open VSX at 1.3.4. Both use ripgrep under the hood.
  • From a .vsix file, if the publisher offers one. Run Extensions: Install from VSIX from the Command Palette and pick the file, or drag it onto the Extensions view. Extensions installed this way don't auto-update, so repeat it for new versions.

The tool I built

Todoscope is my TODO extension. It has its own scanner instead of ripgrep, only counts tags inside real comments, and works the same in Cursor as in VS Code. The tree, highlights and filters are free; Pro adds git blame age, TODOs added on your branch and reports.

Installing it in Cursor: Todoscope is on Open VSX, so search for Todoscope in Cursor's Extensions view (Ctrl+Shift+X) and click Install. It updates on its own like any other extension.

On 95 public repos I hand-checked a sample of 45 lines that only Todo Tree's default pattern reported: about 9 in 10 were not real TODOs (things like BUG("...") calls and TODO = "todo" constants), and Todoscope skips those.

FAQ

Does Cursor have a built-in TODO list?

No. Cursor is built on VS Code and has the same tools: workspace search, a search editor, and the Problems panel for linter warnings. A full tree of TODOs needs an extension.

Why can't I find a VS Code extension in Cursor?

Cursor's Extensions view searches Open VSX, not Microsoft's Visual Studio Marketplace. Some extensions are only on one of them, or have an older version on Open VSX.

How do I install a .vsix file in Cursor?

Open the Command Palette, run Extensions: Install from VSIX, and pick the file. You can also drag the .vsix onto the Extensions view.

Can I ask Cursor's AI to find my TODOs?

You can, but it reads files into the chat, so on a large project it's slower and less complete than search. Search or an extension gives you every match, with clickable line links.
